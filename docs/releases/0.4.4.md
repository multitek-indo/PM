# Multitek PM v0.4.4 — rekonsiliasi alur dan kontrol persediaan

Baseline: `v0.4.3` / `134f5ac6e02a58da861884941e2fb94aaa8443a1`.

## Aturan saldo yang diminta

- **Teknisi mengajukan pemakaian**: saldo **tersedia di aplikasi** langsung berkurang sebesar jumlah; penolakan atau pembatalan mengembalikan sisa yang belum diserahkan **satu kali**. Serah-terima tidak mengurangi lagi; bisa parsial dan bisa mencatat retur fisik.
- **Admin sparepart mengajukan penambahan**: belum berdampak pada saldo. **Manager menyetujui**: saldo buku **bertambah sekali**. Status langsung selesai sehingga tidak ada tindakan “Keluarkan” yang bisa membalik arahnya.
- **Perhatian audit penting**: penambahan oleh approval berarti *penerimaan administratif*, bukan bukti bahwa stok fisik sudah ada di rak. Sebelum saldo ini dijadikan acuan audit fisik, wajib cocokkan dengan nota terima dan opname. Stock opname tetap menghitung fisik terpisah.
- **Mutasi manual dan impor** diajukan oleh admin stok, **diposting hanya setelah persetujuan manager lain**. Ini mencegah jalur input alternatif melewati approval. Impor masuk dan keluar dipisah menurut dokumen; tidak boleh mencampur tanda dalam satu file.
- **Koreksi opname** dihitung oleh admin stok, diposting oleh manager yang berbeda dari pembuat sesi. Perubahan ledger setelah snapshot membuat posting ditolak.

## Pemeriksaan audit

- Event key unik untuk mencegah double posting karena HTTP retry.
- Nomor dokumen dan hash transaksi semantik untuk mencegah unggah ulang CSV/XLSX dalam representasi berbeda; fingerprint raw tetap digunakan.
- XLSX: abaikan metadata dimensi worksheet yang berpotensi under-report, batasi data yang benar-benar dibaca.
- Edit master sparepart tidak lagi menyimpan `current_qty`; mengganti satuan barang yang sudah memiliki transaksi ditolak.
- Jejak waktu, pelaku, sebelum/sesudah perubahan master dan aksi baru pada InventoryAudit.
- Manager mendapat akses lihat work order, foto, opname, mutasi, audit serta rekap pengadaan CSV; bukan izin mengubah checklist.
- Pengelola stok memperoleh permission lihat/tambah/edit mesin, tanpa mengubah membership users. Supervisor PM biasa tidak otomatis dapat menulis stok.
- Ekspor work order mengikuti parameter status/kata kunci di layar; batas 20.000 baris ditampilkan.

## Kompatibilitas & batas otomatisasi

- Migrasi `inventory/0003_v044_audit_integrity.py` **tidak membuat mutasi untuk permintaan historis**. Permintaan lama memakai fase `legacy` dan pemenuhan historis tetap tercatat satu kali ketika diserahkan. Jalur manager yang sebelumnya sudah dikeluarkan secara keliru **harus direkonsiliasi fisik lebih dahulu**; installer akan berhenti jika menemukannya.
- Impor v0.4.3 yang sudah diposting ditandai `posted`; **tidak di-posting ulang**.
- Backup termasuk database, konfigurasi, source dan foto. Restorasi diuji di database sementara. Skrip tidak merestart Odoo, Nextcloud, CCTV, Cloudflared atau Tailscale.
- **Jangan jalankan installer versi lama untuk mengulang deployment.** Gunakan satu installer v0.4.4 yang cocok dengan baseline saja.
- Versi ini tidak mengubah nilai saldo lama secara otomatis. Jika audit ledger menemukan ketidakcocokan, hentikan dan lakukan rekonsiliasi manual sebelum deployment.

## Checklist setelah pemasangan

1. Teknisi buat permintaan 2 dari saldo 10 → saldo tersedia 8; admin menyetujui → tetap 8; menyerahkan → tetap 8.
2. Tolak permintaan teknisi lain yang belum diserahkan → sisa dikredit kembali satu kali.
3. Admin minta 3 → manager setujui → saldo buku naik 3 satu kali; tidak ada tombol “Keluarkan”.
4. Admin membuat dokumen impor → saldo tidak berubah → manager lain memposting → saldo berubah sesuai baris satu kali.
5. Admin stocktake menghitung → manager lain memposting; pemilik sesi tidak dapat menyetujui sendiri.
6. Manager membuka seluruh work order, laporan pengadaan, riwayat stok dan foto hanya baca; teknisi tidak melihat operasi manager.
7. Semua hasil wajib dicocokkan dengan stok fisik gudang, terutama penerimaan administratif dari approval.
