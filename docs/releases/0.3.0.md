# Multitek PM 0.3.0 - Versioning dan identitas perusahaan

Status: rilis fitur pilot. Tanggal paket: 16 Oktober 2026.

## Cakupan yang disetujui

Hanya versioning/rilis dan identitas perusahaan beserta hak aksesnya. Tidak ada perubahan CSS/tema, jam WIB, impor Excel/CSV, penjadwalan, alur pekerjaan, validasi pekerjaan, persetujuan supervisor, nama produk, konfigurasi tunnel, konfigurasi Docker, dependency, atau volume database.

## Versioning

- Nomor aplikasi berasal dari satu file: `app/VERSION.txt`, awal `0.3.0`.
- Sidebar/footer/admin dan respons health menggunakan nomor yang sama.
- Tag standar rilis ini: `v0.3.0`. Tag historis baseline dan `pm-v0.2.0-*` tidak dihapus atau diganti.
- `tools/pm_release.py check` memvalidasi format dan catatan rilis.
- `tools/pm_release.py tag` memeriksa main, melakukan push tag tanpa force dan memverifikasi hasil. Tidak melakukan deployment atau membuat objek GitHub Release otomatis.

## Identitas perusahaan

- Default: **Multitek Indonesia**.
- Menu baru: Administrasi > Identitas perusahaan.
- Dua izin baru yang dapat dipilih dari Grup: **Dapat melihat nama perusahaan** dan **Dapat mengubah nama perusahaan**.
- Grup baru **Pengelola Identitas Perusahaan** berisi dua izin tadi. Tidak ada akun yang otomatis dimasukkan; grup Supervisor PM dan Teknisi PM tidak diubah.
- Untuk membuka admin diperlukan akun aktif dengan Status staf. Status superuser tidak perlu diberikan kepada pengelola nama.
- Nama berubah pada label identitas sidebar/header/login/admin. Nama teknis aplikasi `Multitek PM`, repository, domain, folder, serta data mesin dan histori tetap.
- Pengaturan satu perusahaan per instalasi. Ini bukan sistem multi-tenant dan bukan pemisahan data antarpelanggan.

## Migrasi dan pemulihan

Ada satu migrasi aditif `branding.0001_initial`: tabel profil tunggal, content type, dua permission, satu grup kosong. Tabel operasional maintenance tidak diubah. Nama grup yang sudah ada akan menyebabkan STOP, tidak ditimpa. Nama default hanya dibuat saat migrasi pertama, bukan setiap restart.

Upgrade menyalin kode ke worktree, memakai volume dependency saat ini read-only, menjalankan tes, membuat dump database dan backup source/config/library, lalu mencoba restore serta migrasi pada PostgreSQL sementara terisolasi. Web dan scheduler PM berhenti sebentar saat pergantian source/migrasi; database PM tidak dihentikan.

Rollback otomatis hanya mengembalikan kode lama. Jika migrasi aditif sempat sukses, tabel/permission/grup baru dipertahankan, bukan dihapus atau di-unapply. Migrasi data sengaja tidak memiliki reverse otomatis agar tidak menghapus nama perusahaan. Backup lokal bukan backup seluruh VPS dan bukan backup off-site.

## Verifikasi setelah upgrade

1. Pastikan versi tampil 0.3.0 dan login serta pekerjaan lama masih dapat dibuka.
2. Masuk sebagai superuser, buka Identitas perusahaan. Nama awal harus Multitek Indonesia.
3. Berikan grup baru kepada akun staf uji; pastikan hanya fitur sesuai izin yang terbuka.
4. Coba ganti nama; refresh aplikasi untuk melihat perubahan. Jangan gunakan akun bersama.
5. Uji akun tanpa permission: tidak dapat mengubah dengan membuka URL langsung.
6. Periksa main dan tag v0.3.0 menunjuk commit yang sama. Buat halaman GitHub Release dari tag itu.

## Pengujian

Tes Django kandidat harus lulus pada library VPS dalam database sementara SEBELUM source produksi diganti. Pembuat paket tidak memiliki akses SSH atau token GitHub pengguna. Hasil lokal dan batas pengujian dijelaskan pada file validasi paket, bukan dianggap hasil deployment server.
