# Multitek PM v0.4.0 - Stock opname & permintaan sparepart

Tanggal kandidat: 2026-10-16. Fitur baru setelah 0.3.1. **Rilis belum dianggap terpasang sampai health dan GitHub diverifikasi dari VPS.**

## Cakupan

- Menu baru **Stok sparepart** untuk teknisi dan supervisor lewat browser HP.
- Master sparepart: buat/ubah kode, nama, tipe mesin, satuan, lokasi, stok minimum dan status aktif; saldo tidak dapat diedit langsung.
- Saldo stok dan indikator **perlu restock** (saldo <= batas minimum).
- Permintaan teknisi, opsional terhubung ke work order yang berhak mereka lihat.
- Review setujui/tolak permintaan, lalu keluarkan barang; stok berkurang **hanya pada pemenuhan**.
- Mutasi barang masuk/keluar dengan bukti alasan/nomor referensi dan audit sebelum/sesudah.
- Stock opname: mulai sesi, hitung seluruh item aktif, simpan hitungan per item, posting koreksi selisih dengan pemeriksaan bahwa saldo buku belum berubah.
- Hak kelola: superuser, Supervisor PM, atau anggota grup baru `Pengelola Stok Sparepart` (tanpa anggota otomatis). Teknisi lain hanya melihat stok dan permintaannya sendiri.

## Hal yang sengaja tidak diubah

Dashboard dan jam WIB, tema utama, Excel/CSV mesin, checklist, work order, foto sparepart v0.3.1, grup lama, identitas perusahaan, scheduler, lokasi database/port, Compose, packages, dan layanan non-PM. **Tidak ada data master atau stok fiktif yang dimasukkan otomatis.**

## Batasan

- Stok masih **satu gudang logis** per instalasi. Kolom `location` berupa rak, bukan pembatas stok antarpabrik. Untuk gudang terpisah diperlukan model multi-lokasi dan izin per gudang.
- Belum ada pembelian otomatis, nilai uang/HPP, PO, integrasi supplier, barcode stok, atau impor Excel persediaan.
- Foto kondisi barang tetap berada di work order pada modul foto v0.3.1; permintaan inventory tidak membuat foto baru.
- Maksimum 3.000 item aktif per sesi opname, dan hanya satu sesi opname draf pada satu waktu.
- Perubahan stok saat opname berjalan membuat posting gagal; petugas dapat membatalkan draf dengan alasan (hasil tetap tersimpan sebagai riwayat) dan membuat opname baru tanpa memengaruhi saldo.
- Tidak menambahkan notifikasi otomatis; manager membuka menu permintaan untuk melihat yang tertunda.

## Prosedur singkat pengguna

1. Manager: `Stok sparepart` > `Master sparepart`. Isi kode unik, satuan, lokasi, batas minimum.
2. Manager: `Barang masuk/keluar` > catat stok awal melalui penerimaan dengan referensi dokumen.
3. Teknisi: `Stok sparepart` > `Ajukan kebutuhan`, pilih item dan jumlah; tautkan ke work order jika ada.
4. Manager: `Permintaan` > `Setujui` / `Tolak`; setelah barang benar-benar diserahkan, klik `Keluarkan`.
5. Petugas: `Stock opname` > `Buat opname`, input stok fisik masing-masing dari HP, dan `Posting` setelah semua selesai.
6. Manager: tinjau indikator minimum, permintaan tertunda, dan mutasi terkini dari menu stok.

## Deployment dan rollback

- Script rilis menolak server yang belum berada pada `v0.3.1` atau checkout `main` yang berubah.
- Tes Django (`maintenance`, `branding`, `spareparts`, `inventory`) menggunakan SQLite sementara tanpa akses DB produksi.
- Sebelum deploy: backup PM (kode, konfigurasi rahasia secara privat, PostgreSQL), uji restore dan migrasi di PostgreSQL terisolasi.
- Migrasi hanya menambah tabel `inventory_*` dan grup pengelola stok; tidak menghapus/mengganti struktur lama.
- Setelah berhasil: push commit/tag `v0.4.0` ke `multitek-indo/PM`, tanpa force push. Buat halaman GitHub Release dari tag bila diperlukan.
- Bila rollback kode diperlukan setelah migrasi, **tabel stok tidak dihapus dan database tidak otomatis di-restore**. Jangan memulihkan snapshot DB tanpa memeriksa transaksi baru.
