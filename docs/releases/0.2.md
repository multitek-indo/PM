# Multitek PM 0.2 - Sky Blue, administrasi, jam WIB, dan Excel

Pembaruan ini tidak mengubah model database, aturan persetujuan, interval scheduler,
atau hak akses. Source awal adalah paket PM 0.1 beserta patch HTTPS yang sudah
tersimpan pada checkout pengguna. Script menolak baseline yang telah berubah.

## Perubahan untuk pengguna

### Administrasi

Beranda Administrasi menampilkan kartu menu yang menjelaskan fungsi master mesin,
jadwal, pengguna, grup, work order, riwayat aktivitas, dan status scheduler. Kotak
pencarian menyaring kartu menu, bukan mencari isi database. Tombol Tambah muncul
hanya bila akun memiliki izin yang sesuai. Form mesin dan jadwal dikelompokkan
menjadi bagian yang lebih jelas. Riwayat tetap hanya-baca; pengiriman dan persetujuan
pekerjaan tetap dilakukan di menu Work order. Akun teknisi tidak memperoleh izin
administrasi tambahan dari pembaruan visual ini.

Tema biru muda digunakan di halaman operasional, login, formulir, dan administrasi.
Teks utama tetap biru tua agar terbaca. Warna merah/kuning/hijau dipertahankan untuk
status risiko/peringatan/selesai, bukan diubah menjadi biru. Tema gelap bawaan
Django admin tidak digunakan pada versi ini. Tidak ada font atau tema dari CDN.

### Jam WIB

Dashboard menampilkan jam dengan detik serta tanggal WIB (Asia/Jakarta). Waktu awal
dan sinkronisasi berasal dari server aplikasi; angka berjalan setiap detik di
browser, kemudian sinkronisasi ulang sekitar lima menit atau saat tab dibuka kembali.
Label menunjukkan saat sinkronisasi tidak tersedia. Jam ini tidak mengatur jam OS,
NTP, jadwal, atau tanggal jatuh tempo. Akurasi tetap tergantung jam VPS. Angka KPI
bukan live-stream: muat ulang halaman untuk memperbarui data pekerjaan.

### Impor Excel tanpa konversi CSV

1. Buka **Master mesin > Impor Excel / CSV** menggunakan akun supervisor.
2. Unduh **Template Excel**. Isi sheet `Mesin` mulai baris kedua.
3. Biarkan delapan header di baris pertama. Isi `code` dan `name`; nilai kolom lain
   boleh kosong. Header semua kolom tetap harus ada.
4. Simpan sebagai **Excel Workbook (.xlsx)**. Pilih file lalu klik impor.
5. Kolom nama sheet opsional: kosong berarti memilih sheet `Mesin`, atau sheet
   terlihat pertama bila `Mesin` tidak ada. Nama yang diisi harus sama persis.
6. Jika sukses, halaman master menunjukkan jumlah mesin yang ditambahkan. Bila
   salah satu baris bermasalah, transaksi impor dibatalkan seluruhnya; data lama
   tidak ditimpa.

| Header | Fungsi | Contoh fiktif |
|---|---|---|
| code | Identitas unik mesin, wajib, maksimal 64 karakter | SW-0001 |
| name | Nama mesin, wajib, maksimal 160 karakter | Mesin latihan |
| category | Jenis mesin, maksimal 80 karakter | Sewing |
| manufacturer | Merek, maksimal 80 karakter | Contoh |
| model | Model, maksimal 100 karakter | MODEL-A |
| serial | Nomor seri, maksimal 100 karakter | 000123 |
| site | Pabrik/lokasi, maksimal 100 karakter | PABRIK-UJI |
| line | Line produksi, maksimal 80 karakter | LINE-01 |

Gunakan format **Text** untuk kode dan serial agar angka nol di depan tidak hilang.
Template sudah menggunakan format Text. Tidak ada data contoh pada sheet `Mesin`;
sheet `Contoh` hanya referensi fiktif. Pilih sheet dengan sengaja, jangan mengimpor
contoh sebagai data produksi. Workbook yang diunggah tidak disimpan sebagai lampiran.

Header Indonesia juga didukung, misalnya `kode mesin`, `nama mesin`, `jenis mesin`,
`merek`, `model`, `nomor seri`, `pabrik`, `line produksi`. Urutan kolom boleh berbeda,
tetapi tidak boleh ada header duplikat, hilang, atau kolom tambahan tak dikenal.

**Batas:** 5 MiB untuk XLSX, maksimal 5.000 baris data per sheet (ditambah satu
header); CSV tetap 2 MiB. Workbook dibatasi 30 sheet, 32 kolom, 1.024 entri ZIP dan
25 MiB ukuran total setelah dekompresi. Beberapa workbook kecil dapat ditolak bila
berisi format di banyak baris kosong: hapus format/baris berlebih atau gunakan
workbook template yang bersih.

`.xls`, `.xlsm`, file berpassword, macro, objek tertanam, dan workbook dengan external
links tidak didukung. Untuk `.xls`, gunakan **Save As > Excel Workbook (.xlsx)**;
tidak perlu menjadi CSV. Rumus dan error sel ditolak, bukan dihitung. Gunakan
**Paste Special > Values** untuk nilai identitas yang berasal dari rumus. Kode/serial
numerik lebih dari 15 digit, tanggal, boolean, atau angka pecahan ditolak agar
identitas mesin tidak berubah tanpa disadari.

## Alur satu script upgrade

Script `multitek-pm-v0.2-upgrade.sh` dijalankan di VPS sebagai root. Ia memerlukan
source produksi dan checkout Git yang cocok, branch `main` bersih, remote tepat
`git@github.com:multitek-indo/PM.git`, koneksi SSH yang sudah berfungsi, dan commit
lokal sama dengan main di GitHub. Tidak ada pembuatan kunci atau force push.

1. Pemeriksaan terpadu (source, Git, izin, ruang disk, RAM, status layanan).
2. Worktree/branch rilis terpisah dan volume dependency baru; source produksi hanya
   dibaca. Pemasangan tiga wheel dengan checksum membutuhkan koneksi PyPI.
3. Tes lengkap Django/SQLite pada helper Docker terisolasi tanpa jaringan,
   tanpa kredensial produksi, dan tanpa volume database produksi.
4. Backup konfigurasi/source, database PM, role PostgreSQL PM, dan dependency lama.
5. Restore penuh backup database ke PostgreSQL sementara tanpa published port.
   Container/volume uji yang dibuat script sendiri dibuang setelah verifikasi.
6. Pemeriksaan file rahasia dan commit rilis lokal (belum push).
7. Stop sementara **hanya web dan scheduler PM**, tukar source dan volume dependency.
8. Pemeriksaan health, halaman login, render admin/dashboard/import, port,
   resource, dan status layanan lama. Kegagalan mencoba rollback code/config.
9. Push commit dan tag dengan mekanisme biasa, verifikasi remote, lalu fast-forward
   checkout main lokal hanya bila belum berubah.

Tes sementara dan instalasi library menambah beban host walau dibatasi. Jalankan
ketika tidak ada teknisi mengirim formulir; halaman PM terputus sementara saat tahap
7. Database PM, Nextcloud, Odoo, CCTV, Tor, Portainer, Cloudflared, dan Tailscale tidak
dihentikan/restart oleh script. Berbagi host tetap berarti tidak ada jaminan nol
kontensi sumber daya.

## Backup dan pemulihan

Backup disimpan dengan izin root-only pada:

```text
/var/backups/multitek-pm/<waktu-UTC>-<kode>/
  source-config.tar.gz
  database.dump
  postgres-roles.sql
  packages-before.tar.gz
  SHA256SUMS
  restore-check.txt
  upgrade.log
```

File konfigurasi sebelum perubahan juga disimpan; beberapa memuat password. Jangan
unggah folder backup, `.env`, SQL role, atau log privat ke GitHub. Backup ini untuk
**PM saja**, bukan seluruh VPS/Nextcloud/Odoo. PostgreSQL dump merupakan snapshot
konsisten pada saat dump, bukan perlindungan transaksi yang masuk setelah dump.
Source/config tidak berubah selama fase pengambilan backup dan diperiksa lagi
sebelum deployment. Data restore sementara diperiksa, bukan ditampilkan per mesin.

Backup di disk VPS yang sama tidak melindungi dari disk rusak, kehilangan VPS, atau
bencana lokasi. Salin terenkripsi ke lokasi lain setelah proses berhasil; aturan
retensi harus ditentukan terpisah. Script tidak menghapus backup lama.

Jika deployment gagal, script mencoba mengembalikan source, `.env`, Compose dan
volume dependency lama, lalu memeriksa health aplikasi. **Database tidak direstore
secara otomatis**, agar transaksi baru tidak hilang. Jika rollback tidak lolos,
hentikan perubahan lanjutan dan periksa `upgrade.log` serta state di
`/opt/multitek-pm-releases/<waktu>/state.json`; jangan gunakan installer awal, `prune`,
`down -v`, atau force push sebagai perbaikan.

Jika muncul **PARTIAL SUCCESS**, aplikasi baru sudah lolos tetapi push gagal.
Jalankan script yang sama untuk melanjutkan **push saja**, bukan ulang backup/deploy.
Perubahan main dari pengguna lain tetap menyebabkan penolakan; lakukan review
Git, bukan force push. Jika muncul STOP sebelum deployment, kode aktif tidak diganti.
File kandidat, commit dan backup tetap ada untuk pemeriksaan.

## Pengujian dan penerimaan

Di lingkungan penyusunan, parser Excel, logika jam, sintaks, dan orchestrator diuji
terpisah. Django/PostgreSQL/Docker tidak tersedia untuk eksekusi integrasi di
lingkungan tersebut; jangan menganggapnya pengujian di VPS pengguna. Script harus
menjalankan suite asli beserta tambahan sebelum menyentuh runtime.

Setelah PASS, lakukan hard refresh Ctrl+F5. Periksa admin mesin/jadwal/pengguna,
jam berdetik dan WIB, impor workbook valid, pesan kode duplikat, tidak ada insert
parsial pada file salah, CSV lama, login/logout, dan persetujuan teknisi/supervisor.
Gunakan kode mesin uji yang tidak berbenturan; impor tidak menghapus data uji otomatis.
Jangan menguji dengan data pelanggan sensitif pada screenshot atau repo.
